# CRM-system

Система управления взаимоотношениями с клиентами (CRM) для отслеживания воронки продаж: от рекламных кампаний до активных клиентов.

## Технологии

| Компонент | Технология |
|-----------|------------|
| Backend   | Django 6.x |
| База данных | PostgreSQL 18 |
| Веб-сервер | Gunicorn + Nginx (для статики) |
| Контейнеризация | Docker, Docker Compose |
| Управление зависимостями | uv |

## Основные возможности

- 🏷 Управление **услугами** (продуктами)
- 📢 Управление **рекламными кампаниями**
- 👤 Ведение **лидов** (потенциальных клиентов)
- 📄 **Контракты** и их привязка к услугам
- ✅ Перевод лида в **активного клиента**
- 📊 **Статистика** по рекламным кампаниям (количество лидов, активных клиентов, прибыль и ROI)
- 🔐 Ролевая модель (Оператор, Маркетолог, Менеджер, Администратор)
- 🔑 Авторизация и регистрация пользователей

## Быстрый старт

### Требования

- Python 3.12+
- **uv** (или Poetry / pip)
- PostgreSQL 18 (или Docker)
- Docker (опционально, для контейнеризации)

### Переменные окружения

Создайте файл `.env` в корне проекта (рядом с `manage.py`) и задайте следующие переменные:

| Переменная | Описание | Пример | Обязательная |
|------------|----------|--------|--------------|
| `POSTGRES_USER` | Имя пользователя БД | `admin` | ✅ |
| `POSTGRES_PASSWORD` | Пароль БД | `secure_password` | ✅ |
| `POSTGRES_DB` | Название базы данных | `admin-db` | ✅ |
| `POSTGRES_HOST` | Хост БД (для Docker – `db`) | `localhost` | ✅ |
| `DJANGO_LOGLEVEL` | Уровень логирования | `INFO` | ✅ |
| `DJANGO_SECRET_KEY` | Секретный ключ Django | генерируется | ✅ |
| `DJANGO_DEBUG` | Режим отладки | `True` / `False` | ✅ |
| `DJANGO_ALLOWED_HOSTS` | Разрешённые хосты | `localhost,127.0.0.1` | ✅ |

Пример файла `.env`:

```env
POSTGRES_USER=admin
POSTGRES_PASSWORD=admin
POSTGRES_DB=admin-db
POSTGRES_HOST=db
DJANGO_LOGLEVEL=INFO
DJANGO_SECRET_KEY=django-insecure-...
DJANGO_DEBUG=True
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1

Установка и запуск (локально)

    Клонируйте репозиторий и перейдите в папку crm:

bash

git clone <url>
cd CRM-system/crm

    Установите зависимости через uv:

bash

uv sync

    Примените миграции:

bash

python manage.py migrate

    Создайте суперпользователя:

bash

python manage.py createsuperuser

    Инициализируйте роли (группы и разрешения):

bash

python manage.py init_roles

    Запустите сервер разработки:

bash

python manage.py runserver

Приложение будет доступно по адресу http://127.0.0.1:8000.
Запуск в Docker (production‑подобный режим)

В корне проекта (там, где docker-compose.yaml) выполните:
bash

docker compose up --build

    Веб-интерфейс: http://localhost

    Админка: http://localhost/admin/

Остановка и очистка (данные БД сохраняются в volume db_data):
bash

docker compose down -v   # удаляет все volumes, включая БД

Управление через терминал внутри контейнера
bash

# Найти контейнер
docker ps

# Подключиться к контейнеру
docker exec -it <container_name> /bin/sh

# Выполнить команды Django
python crm/manage.py migrate
python crm/manage.py createsuperuser
python crm/manage.py init_roles

Роли пользователей

Роли создаются командой init_roles. Каждая роль имеет свой набор прав:

    Администратор – полный доступ через Django Admin (создание/редактирование пользователей, всех моделей).

    Оператор – может создавать, просматривать, редактировать и удалять лидов.

    Маркетолог – может управлять услугами и рекламными кампаниями.

    Менеджер – может просматривать лидов, переводить их в активных клиентов, а также управлять контрактами (CRUD).

    Все роли имеют доступ к просмотру статистики рекламных кампаний.

Основные команды для управления
    
    python manage.py init_roles	Создаёт группы (роли) и назначает им права доступа
    
    python manage.py migrate	Применяет миграции
    
    python manage.py createsuperuser	Создаёт суперпользователя (администратора)
    
    python manage.py collectstatic	Собирает статику для продакшена
    
    python manage.py cleanup_unused_media   Очистка неиспользуемых медиа
    
    python manage.py cleanup_empty_media_dirs   Удалить все пустые каталоги в MEDIA_ROOT - каталог media

    python manage.py static_autocollect автосбор статики онлайн
    
    python manage.py static_autocollect > /dev/null 2>&1    автосбор статики в фоне

Для локальной разработки рекомендуется использовать DEBUG=True и встроенный сервер runserver.
Статика автоматически обслуживается Django в режиме отладки.

Дополнительные возможности

    Загрузка документов (контракты) – файлы сохраняются в media/documents/YYYY/MM/DD/.

    Автоматическое добавление нового пользователя в группу «Оператор» при регистрации (реализовано в RegisterView).

    Преднастроенные разрешения для каждой роли.

Безопасность

    Никогда не коммитьте файл .env в репозиторий.

    Для продакшена обязательно установите DJANGO_DEBUG=False и укажите реальные домены в DJANGO_ALLOWED_HOSTS.

    Генерируйте уникальный DJANGO_SECRET_KEY для каждого окружения.

Для проверки кода использван линтер pylint, конфигурация в .pylintrc

    pylint crm/

Для просмотра документации swagger '/docs'
